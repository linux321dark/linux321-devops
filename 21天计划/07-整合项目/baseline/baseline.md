# 基线量化表（阶段 0 交付物 · 填完才算有基线）

> **配套**：[`../L1-巨石应用云原生化.md`](../L1-巨石应用云原生化.md) §3.9 · 阶段 0 的唯一产出就是这份表。
> **填写规则（三条，缺一条这份表就不算数）**：
> ① 每行都要有**测量方法**——写清用什么命令、哪个页面、哪个系统查的；
> ② 每行都要有**数据来源**——截图/工单/监控导出，**没有方法的数字不算基线**；
> ③ 采集不全的项，写 `暂无/估算/回溯` 并注明原因，**不要留空、也不要编**。

## 二、每个数字都要能回答这三个追问

填完任意一行，自问：

1. **这个数怎么来的？**（说不出命令 = 没测）
2. **它在什么条件下成立？**（什么时段、什么负载、几个副本）
3. **它变了怎么知道？**（谁在什么时点会重新量它）

> 第 3 问是给"阶段 7 之后"准备的：**基线不是一次性的，是要能被复测的**。没有第 3 问，改造完无法证明收益。

## 三、基线快照归档

测完把原始数据放这里，**不要只填表、丢掉原始件**：

```
baseline/
├── baseline.md            ← 本表（结论）
├── evidence/              ← 原始证据
│   ├── 2026-XX-XX-images.txt        # docker images 输出
│   ├── 2026-XX-XX-pipeline.txt      # CI 耗时导出
│   ├── 2026-XX-XX-traffic.csv       # 峰谷数据导出
│   └── screenshots/                  # 监控面板截图
└── traffic-profile.md     ← 峰谷曲线
```

> **为什么单列 evidence/**：三个月后有人质疑"当时测的是不是这个环境"，**只有原始输出能回答**。表是结论，证据才是事实。
