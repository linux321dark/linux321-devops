## 三、峰谷特征四问

填完这张表，要能回答：

| 问 | 你的答案 | 依据 |
|---|---|---|
| **峰在什么时候？**（几点到几点） | | |
| **峰值持续多久？**（决定用 HPA 还是预留副本） | | |
| **谷有多长？**（多长的低负载窗口适合缩容） | | |
| **有没有突发尖峰？**（秒级还是分钟级） | | |

> **第 4 问决定 HPA 能不能救**。**HPA 的反应链路是 15s 采集 + 15s 同步 + 调度拉镜像 + 就绪探针，实测 1–2 分钟。** 秒级尖峰 HPA 追不上，只能靠 `minReplicas` 预留 + 网关限流兜底。**把"有尖峰"写成"没有"，会让整条弹性设计建在流沙上。**

## 四、由峰谷推出的三个参数

| 参数 | 取值 | 怎么来的 |
|---|---|---|
| HPA 目标利用率 | | **日常峰值利用率 × 1.2** 对应的水位，落在 50–70% 区间；再高则压不住峰，再低则常年在扩 |
| `minReplicas` | | 谷值所需副本数；**若谷值接近 0，说明夜间缩容是主要收益来源** |
| `maxReplicas` | | 峰值 QPS ÷ 单副本承载 QPS，并留 30% 余量，**再按节点余量反推**（不能只看 Pod 数） |

> **峰值利用率 × 1.2 这个系数是经验值不是标准**，但"用峰值而不是均值"这件事是硬道理——**按均值配阈值，峰值必然扩容不及。**

## 五、夜间缩容能省多少（算法，不是数字）

```
夜间可缩副本数 = 峰谷差值 × 可缩时长
节省比例 ≈ (可缩副本数 / 峰时副本数) × (可缩时长 / 全天时长)
```

**注意扣减项**（算的时候别忘）：

- **缩容窗口 300s**：缩容不是瞬间完成的，**至少 5 分钟的窗口期内副本数不会掉**
- **HPA 生效延迟 1–2 分钟**：负载下来后要等判定 + 同步
- **`minReplicas` 是收益地板**：谷时至少保留几个副本，这部分省不掉
- **流量本身有夜间波动的部分**：不是所有低谷都是"可缩的"

> **在拿到真实 ACK 账单之前，不要报任何百分比。** 用本表的峰谷数据 + 上一份 [`baseline.md`](baseline.md) 的实测资源值，**先把公式算出来，等账单一到就能代入。**
