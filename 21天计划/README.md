> 资料分三层，**各管一件事，不重复**。先认清自己在哪一层，再往下读。

| 层 | 你要解决的问题 | 打开哪个 |
|---|---|---|
| **方法层** | 「这个报错什么意思」「这个字段怎么填」「这段 yaml 哪错了」 | [`00-授渔篇-怎么自己搞懂.md`](00-授渔篇-怎么自己搞懂.md) |

## 两种用法

**用法 A · 按 21 天推进（主线）**
打开当天的日课 → 先读第四节的指向（去读教材层的对应篇）→ 回日课做实战 → 按第六节验证 → 背第八节话术。
**顺序不要反**：先读教材再做实战，命令才不会变成敲键盘。

**用法 B · 按需查（面试前突击）**
1. 先看 [`00-学习地图与前置依赖.md`](00-学习地图与前置依赖.md) 的「完整篇目索引」定位组件
2. 打开该篇，**先读第 0 节知识图谱**（一眼看清这篇覆盖什么）
3. 直接跳到第 4 段「逐字段表」查你要的字段、第 6 段「踩坑与排障」查你要排的错
4. 需要出处时翻第 7 段来源表，或直接查 [`09-参考索引/README.md`](09-参考索引/README.md)

三段一律给成品答案：**不写"你觉得呢""想一想"，直接给可背的话、可抄的动作、可对照的判断标准。**

### 授渔篇：命令之外的"怎么自己搞懂"


九段结构给的是**结果**——可背的话术、可复制的命令。但命令是别人验证过的路径，**换一个报错、换一个组件就失效**。所以另设一篇通用方法，21 天每天用同一套动作：

| 方法 | 一句话 |
|---|---|
| **三态模型** | 期望态（yaml）→ 实际态（集群）→ 协调（controller）；所有命令归三类，排障按"yaml 错→协调卡→应用错"三层走 |
| **五个自查动作** | `api-resources` 查对象 / **`kubectl explain` 查字段** / `get -o yaml` 看真实态 / `describe` 看 Events / `get events` 看时间线 |
| **陌生 yaml 四问** | 是什么（kind）→ 要什么（spec）→ 现在怎样（status）→ 谁在管（controller） |
| **三层兜底** | `--help` → `explain` → 官方文档（不搜博客，版本会不匹配） |
| **三问自测** | 能说输入输出？能故意改坏再倒推？能画上下游？ |

**用它的时机**：每天动手前扫一眼三态模型；遇到日课单页没写到的报错，按"症状→状态→Events 的 Message"三层往下挖，不要先重装。
